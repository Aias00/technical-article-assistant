# 代码示例与配置验证

按文章中的用途分类，避免既夸大验证也盲目运行：

- 可执行示例：读取源码/官方文档，核对依赖版本、API签名和前提；有合适执行工具时，在隔离临时目录复现。
- 片段/伪代码：检查语义及假设，标“片段/伪代码，不是独立可运行程序”；不为凑可运行性编造业务组件。
- 生产命令、带凭据或会产生外部写入的代码：不因核稿请求而直接执行；只在已有授权范围内验证，无法执行则记录原因。
- 配置：优先用现有解析器、类型检查或官方校验工具；只有语法通过不能证明部署成功。

不自动执行inspect_article.py发现的任意代码。宿主先读懂代码，确认依赖、权限和副作用，再选择合适验证方式。不要自动安装和执行不可信包，不修改用户项目以迁就示例。

## verification.md记录

每个需验证的代码块记录：

- 标识/段落位置与代码摘要，关联inspection.json代码块标识（若有）。
- 类型、固定依赖版本、语言版本、操作系统和必要前提。
- 实际执行的命令、退出码、输出摘要、对应日志路径。
- 结果：passed / failed / not_run / not_applicable。
- 无法验证的具体原因；片段只做静态检查时明确范围。
- 文章声称的输出是否与实际运行一致，缺少性能测量时不能根据一次运行证明提效比例。

版本或API无法确认时先查官方资料，不凭记忆修成另一个未经验证的调用。发现错误时在review.md注明，再修订、重跑并更新记录。
仅缺少执行能力不自动等于示例错误，但必须披露not_run；关键结论依赖尚未执行的实验时，发布结论保持待修订或阻断。

inspect_article.py中的not_run只代表脚本未执行示例；宿主执行记录放verification.md，不把本地检查的passed改称“代码运行通过”。
