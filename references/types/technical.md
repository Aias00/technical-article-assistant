# 技术文章

## 核稿

核对技术事实、版本/API、前提、机制、实现和验证边界。官方文档、对应版本源码、实际日志和实验记录优先；有检索或源码能力时主动查关键主张，记录URL/源码位置及适用版本。
操作教程检查完成目标所需的步骤、依赖与验证方法；架构分享检查组件职责、数据流和取舍，不强制包含命令。
涉及可执行代码、配置或性能结论时才加载code-verification.md。缺少运行环境要记not_run，不自动当错误；性能结论缺测量依据不能当实测结果发布。

## 文章与PPT

文章按需要组织：问题与背景 → 前提和约束 → 机制/方案 → 示例或实施 → 验证 → 限制。
演示突出问题、关键机制、证据和适用边界；代码只展示讲解所需片段，保留完整内容在文章中。不要把路线图当已发布能力。
